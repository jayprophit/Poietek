POIETEK / STUDIO DAW STATION (SDS)
MASTER DEVELOPMENT LIBRARY — VERSION 1.2 ADDENDUM

17 — DJ, DVS, LIVE REMIX, SET PREPARATION & PERFORMANCE ARCHITECTURE
=====================================================================

PURPOSE

This document converts the creator-supplied DJ-software comparison and verified
first-party product capabilities into an original Poietek/SDS subsystem.

The goal is NOT to clone Serato, rekordbox, Traktor, VirtualDJ, djay, Mixxx or
Ableton Live. The goal is to understand the functional principles that successful
DJ/performance tools solve, then implement original Poietek/SDS workflows using
the same canonical project, asset, hardware and collaboration architecture.

The current SDS repository already contains a DJ workspace prototype. Treat that
as an interface sketch. This document specifies the engine and data architecture
required to make DJ mode a real performance system.

------------------------------------------------------------------------------

C. BEATGRIDS / VARIABLE TEMPO

Serato documentation shows the importance of editable beatgrids, especially for
material with changing tempo, and Traktor Pro 4 currently advertises flexible
beatgrids designed to follow tempo changes.

Poietek/SDS needs `TempoMapAnalyzer`.

BeatGrid {
  downbeat
  beatMarkers[]
  barMarkers[]
  tempoSegments[]
  confidence
  locked
}

Modes:
Fixed BPM
Variable Tempo
Free / No Grid
Manual Grid
Imported Grid

Grid operations:
Set downbeat
Move marker
Add tempo marker
Stretch region
Reset section
Lock
Analyze selected region

Sync must use the tempo map rather than only an average BPM.

D. SYNC

Implement multiple behaviors rather than one magic Sync button.

OFF
No sync.

TEMPO SYNC
Match tempo but leave phrase/bar position under performer control.

BEAT SYNC
Match tempo and beat phase.

PHRASE ASSIST
Optional suggested drop/transition points using phrase analysis, not forced.

LINK / EXTERNAL CLOCK
Support external synchronization adapters such as MIDI Clock and Ableton Link
where platform/API support exists.

Manual beatmatching remains fully supported.

E. DVS / TURNTABLE CONTROL

Serato, Traktor, VirtualDJ, Mixxx and djay all demonstrate the continuing value
of Digital Vinyl Systems.

Create `DvsEngine`.

Responsibilities:
- receive stereo timecode input;
- calibrate signal;
- detect speed;
- direction;
- relative/absolute position when control signal supports it;
- needle/drop behavior;
- scratch movement;
- input-level/quality display;
- dropout/noise resilience;
- latency compensation;
- deck routing.

DvsCalibration {
  inputDevice
  inputChannels
  signalType
  mode
  noiseFloor
  signalStrength
  channelBalance
  polarity
  calibrationQuality
  latencyOffset
}

User-facing modes:
ABSOLUTE
RELATIVE
INTERNAL

Important clean-room/legal rule:
Timecode formats/protocols may be proprietary.
Support only documented/open/licensed formats or user-authorized generic
compatible signal modes after legal review.

Never copy proprietary decoder code.

F. SCRATCH / JOG ENGINE

DVS and platter/jog control require a different quality bar from ordinary
timeline scrubbing.

Requirements:
- very low control-to-audio latency;
- stable reverse;
- rapid acceleration/deceleration;
- key-lock behavior option;
- vinyl brake/start curves;
- slip mode;
- backspin;
- needle search;
- motorized platter feedback adapters where documented.

Add a `ScratchTransport` layer that converts hardware motion into sample-position
changes with interpolation and no audible discontinuity.

H. STEM CROSSFADER / MORPHING

Original Poietek concept:
A normal crossfader can be switched into a multi-layer transition surface.

Examples:
Deck A vocal -> Deck B vocal
Deck A drums -> Deck B drums
Bass held from A while music changes to B
Vocals removed during transition

Represent crossfade as automation curves over stem buses, not destructive audio.

X. PERFORMANCE RELIABILITY

DJ/live mode must have a stricter runtime policy than ordinary editing.

Before performance:
preload critical media
precompute waveform/beatgrid/stems where possible
verify audio device
verify controller
verify sample rate
verify mapping
disable sleep
show battery/power
show missing/offline assets
show storage
show CPU/GPU
show network only if required

Performance Guard:
prevents background project migrations/large downloads/AI jobs from causing
audio dropouts during a live set.

Y. OFFLINE-FIRST DJ

Once a set and its permitted media are stored locally:
- open set offline;
- analyze local files offline;
- use decks;
- use DVS;
- use local stems/models;
- use controller mappings;
- record set;
- video/VFX from local assets;
- export history.

Cloud sync and streaming are enhancements, not requirements.

4. CURRENT SDS DJWORKSPACE MIGRATION
------------------------------------------------------------------------------

Keep:
- recognizable two-deck performance metaphor;
- physical-hardware orientation;
- faders/jog/FX concepts.

Replace:
- simulated deck state with DeckEngine;
- fake local UI timing with audio clock;
- hardcoded controller assumptions with MappingService;
- one-screen-only DJ state with PerformanceSet domain objects;
- visual-only FX with real AudioGraph nodes;
- fake waveform with asset-derived peaks;
- fake sync with BeatGrid/SyncEngine;
- fake scratch with ScratchTransport.

The existing component should eventually be renamed from a generic demo
`DJWorkspace` implementation into a view layer over the performance services.

9. PERFORMANCE GRID + DAW CONVERGENCE
------------------------------------------------------------------------------

One of Poietek's strongest differentiators should be that a beatmaker does not
have to export a song to a separate DJ program just to perform it.

Production Arrangement
-> Publish to Performance Scene
-> stem groups automatically available
-> loops/hot cues suggested
-> performance pads generated
-> DJ version can be remixed live
-> live performance recorded back into Arrangement.

This connects the DAW, sampler, stems and DJ system directly.

13. CLEAN-ROOM / LICENSING NOTES
------------------------------------------------------------------------------

Mixxx is open-source and currently states GPLv2 licensing in its official GitHub
repository. Study its architecture and user-facing principles, but integrating
GPL code into Poietek has licensing consequences. Do not copy code unless the
entire intended distribution model is compatible or legal counsel approves.

Other referenced products are proprietary. Use only published capabilities and
documented/open interoperability methods.

Avoid public feature names that imply affiliation:
Serato Mode
rekordbox Mode
Traktor Deck
VirtualDJ Mixer
etc.

Use original Poietek terms.
