POIETEK / STUDIO DAW STATION (SDS)
MASTER DEVELOPMENT LIBRARY — VERSION 1.4 ADDENDUM

20 — OPEN RESOURCES, THIRD-PARTY RESEARCH & FIRST WEB PROTOTYPE BACKEND
======================================================================

PURPOSE

Poietek should deliberately reuse high-quality public standards, open-source
libraries, open research and model ecosystems rather than reinvent every low-level
component.

At the same time, proprietary/closed products can be studied for published
workflow and capability inspiration.

Nothing enters the production codebase merely because it is available online.

Every dependency/model/resource must pass:
- technical review;
- licence review;
- security review;
- maintenance/health review;
- platform review;
- provenance/data-rights review where applicable.

------------------------------------------------------------------------------
1. RESOURCE CLASSIFICATION
------------------------------------------------------------------------------

ADOPT
Licence/architecture are suitable and project approves direct dependency.

EVALUATE
Promising; prototype/benchmark before commitment.

REFERENCE ONLY
Study algorithms/API/workflow, but do not include code/assets.

LICENCE REVIEW REQUIRED
Potentially useful but licence obligations may conflict with project distribution.

VENDOR / COMMERCIAL OPTION
Could be licensed later.

RESEARCH
Paper/prototype not suitable for production yet.

DEPRECATED / ARCHIVED
Do not build critical future architecture around it without a maintained fork.

------------------------------------------------------------------------------
4. GITHUB AS RESEARCH SOURCE
------------------------------------------------------------------------------

Use GitHub for:
- open-source libraries;
- DSP implementations;
- test fixtures;
- device mapping examples;
- protocol libraries;
- UI frameworks;
- build tools;
- standards implementations;
- plugin SDK examples;
- issue discussions describing edge cases.

Research procedure:
1. record exact repo/commit/tag;
2. inspect licence;
3. inspect activity/maintenance;
4. inspect security advisories;
5. inspect transitive dependencies;
6. classify;
7. prototype behind adapter;
8. add tests;
9. document decision.

Do not paste code from a repository before licence classification.

------------------------------------------------------------------------------
5. HUGGING FACE AS MODEL/DATA RESEARCH SOURCE
------------------------------------------------------------------------------

Hugging Face currently provides versioned repositories for models, datasets and
Spaces and documents Xet-backed large-file handling; it also offers storage
buckets.

Poietek use cases:
- discover source separation models;
- pitch/transcription models;
- speech/music embeddings;
- tagging/classification;
- transcription/captioning;
- visual generation/research;
- publish Poietek-compatible open models;
- benchmark alternatives;
- maintain model cards.

MODEL IMPORT GATE

Before enabling a model:
- model licence;
- code licence;
- dataset/training provenance if known;
- commercial-use permissions;
- derivative restrictions;
- attribution;
- architecture compatibility;
- model size;
- inference memory;
- offline capability;
- latency;
- quality benchmark;
- malicious/custom-code risk.

Never enable "trust remote code" automatically.

------------------------------------------------------------------------------
6. CLOSED / PRIVATE PRODUCT INSPIRATION
------------------------------------------------------------------------------

Proprietary tools are legitimate sources of high-level product research through:
- public documentation;
- product demos;
- publicly available UI;
- reviews;
- patents as legal/technical research;
- user feedback;
- published APIs;
- documented interoperability.

Examples already covered in the Poietek library:
DAWs
pitch editors
DJ software
synth/effect suites
video/VFX editors
creative platforms

Clean-room rule:
Research team writes capability requirements.
Implementation team works from requirements/open specifications, not copied
private code/assets.

Do not solicit leaked source code, stolen SDKs, cracked products, confidential
documents or bypassed vendor protections.

------------------------------------------------------------------------------
7. PATENTS
------------------------------------------------------------------------------

Patent publications can inspire research but publication is not permission.

For novel/high-risk implementation areas:
- polyphonic note editing;
- advanced source separation;
- DVS protocols;
- time stretching;
- proprietary hardware transfer;
- ML audio transformations;

create:
PriorArtRecord
PotentialPatentConcern
FTOReviewStatus

Avoid implementing a known active claim solely because its patent text is public.

8. FIREBASE FIRST-WEB-PROTOTYPE OPTION
------------------------------------------------------------------------------

The creator has access to a Firebase hobbyist/no-cost setup and may use it for the
first Poietek Web prototype.

Design Firebase as an adapter, not the canonical backend.

FirebaseBackendAdapter:
Authentication
Firestore
Hosting
App Check
Crashlytics/Performance where desired
Cloud Messaging later

MEDIA STORAGE:
Do NOT require Firebase Cloud Storage for the Spark prototype.

Current Firebase documentation states that as of 3 February 2026 access to Cloud
Storage for Firebase requires the Blaze billing plan, even though no-cost usage
may still exist after upgrading.

Therefore the first no-billing prototype can use:
- local IndexedDB/OPFS for media;
- Firestore for metadata/collaboration prototypes;
- external BYOC storage connectors from Document 19;
- optional Supabase/object storage later.

------------------------------------------------------------------------------
11. FIREBASE VS SUPABASE PROTOTYPING
------------------------------------------------------------------------------

Firebase strengths:
- quick web/mobile onboarding;
- mature Firebase tooling;
- no-cost Spark usage for many development scenarios;
- Hosting/Auth/Firestore integration.

Supabase strengths:
- relational PostgreSQL foundation;
- SQL;
- open-source/self-host options;
- Realtime/Auth/Storage ecosystem.

Poietek should avoid ideological dependence on either.

Prototype choice may be Firebase because the creator already has an account.
Canonical architecture remains provider-neutral.

16. SECURITY
------------------------------------------------------------------------------

Never execute downloaded repository/model code inside the main DAW automatically.

Use:
sandbox
WASM where applicable
worker/process isolation
hash validation
signed releases
allowlist/review
network permissions
filesystem permissions

Model files are treated as untrusted external content.

------------------------------------------------------------------------------
18. FIREBASE COST GUARD
------------------------------------------------------------------------------

For Spark prototype:
- conservative Firestore writes;
- batch/debounce project metadata;
- do not write mixer meters/playhead every animation frame;
- do not store large waveforms as Firestore documents;
- do not sync PCM/video through Firestore;
- cache locally;
- surface quota errors cleanly.

If quota unavailable:
app remains locally usable.
