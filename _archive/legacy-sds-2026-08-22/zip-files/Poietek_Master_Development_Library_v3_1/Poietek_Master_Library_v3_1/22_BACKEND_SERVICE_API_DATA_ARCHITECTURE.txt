22 — BACKEND, SERVICE LAYER, API & DATA ARCHITECTURE
====================================================

PURPOSE

This document defines the backend architecture that supports:
accounts, teams, sync, collaboration, storage connectors, community, rights,
publishing, notifications, search and AI jobs.

Critical distinction:

THE BACKEND IS NOT THE AUDIO ENGINE.

Realtime creative playback/recording lives on the client/native engine.
Backend services support persistence, synchronization and network features.

------------------------------------------------------------------------------
1. BACKEND PRINCIPLES
------------------------------------------------------------------------------

1. LOCAL FIRST
Backend outage does not stop local project work.

2. PROVIDER ABSTRACTED
Firebase/Supabase/self-hosted are adapters.

3. SERVICE BOUNDARIES
Do not make one giant API server.

4. EVENT DRIVEN WHERE USEFUL
Uploads/transcodes/notifications/search indexing happen asynchronously.

5. IDEMPOTENT
Retrying a sync/upload operation should not duplicate state.

6. AUDITABLE
Permissions, release approvals, rights changes and monetary operations logged.

7. LEAST PRIVILEGE
Services only access required data.
