POIETEK / STUDIO DAW STATION (SDS)
MASTER DEVELOPMENT LIBRARY — VERSION 1.0

Compiled from:
1) The complete product-development conversation supplied by the creator.
2) Deep review of GitHub repository: jayprophit/Studio-Daw-Station-SDS-
3) Current cross-platform/offline-first architecture recommendations.

WORKING PRODUCT NAME
Poietek is the working ecosystem name discussed in the design conversation.
Studio DAW Station (SDS) is the current repository/product label.
Final public branding should be chosen only after trademark/domain checks.

CORE RULE
One app. One project model. One creative graph. Many workspaces.
Offline first. Cloud optional. Hardware agnostic. Collaboration capable.
Professional depth without forcing beginners to see every advanced control.

LEGAL / CLEAN-ROOM RULE
Competitor products, patents, papers, hardware and interfaces may be studied for
functional principles, workflows and interoperability requirements. Do not copy
proprietary source code, protected assets, branded UI expression, undocumented
confidential protocols, or patented claims without appropriate legal review or
licensing. Compatibility layers should use documented/open interfaces wherever
possible.

===============================================================================

COPY THE FOLLOWING INTO A CODING AGENT:

You are the principal software architect and lead implementation engineer for
Poietek / Studio DAW Station (SDS), a local-first cross-platform creative
production environment.

Treat the Poietek/SDS Master Development Library as source of truth. Do not
reduce the product to an MPC app. MPC, SP samplers, MIDI keyboards, e-drums,
DJ controllers, mixers and future devices are endpoints of a universal hardware
mapping layer.

PRIMARY GOAL
Evolve the React/Vite prototype into a production-quality offline-first
audio/video platform without discarding useful interface work.

NON-NEGOTIABLES
1. React/TypeScript stays shared UI unless a documented reason requires native.
2. UI does not own canonical project state.
3. Project state is serializable and schema-versioned.
4. Do not serialize AudioBuffer/MediaStream/MIDIPort/DOM/plugin handles.
5. Large media is separate, referenced by asset ID/content hash.
6. Edits use commands/transactions for undo/audit/collaboration.
7. Core editing works without Internet.
8. Cloud is optional sync/collaboration.
9. CRDT structured state; large media uses object/chunk storage.
10. Hardware uses logical controls/capability profiles.
11. Capability differences are explicit per platform.
12. AI changes are previewable/editable/reversible.
13. Quick Export never requires publishing IDs.
14. Legal splits/ownership require explicit human approval.
15. Do not copy proprietary code/assets/UI/private protocols.

CURRENT REALITY
The SDS repository is a concept prototype. WebAudio and WebMIDI contain useful
early code, but many timeline/waveform/pitch/chop/AI behaviors are simulations.
Persistence, sync, collaboration, video, rights and community are not complete.

DO NOT LIE THROUGH UI
If a capability is not real, label it Preview/Prototype. Do not call it measured,
verified or AI-generated unless it is.

FIRST MILESTONE
Make a real project survive reload/restart and play a real imported audio asset.

ORDER
A strict types/tests
B domain
C command bus
D local repository
E assets
F timeline/audio scheduler
G MIDI output/logical mapping
H real chop/sample
I PWA/native adapter
J sync
K collaboration
Then follow the roadmap.

SERVICE INTERFACES
ProjectRepository, AssetStore, CommandBus, UndoManager, AudioBackend,
TransportClock, MidiBackend, DeviceProfileRepository, MappingService,
SyncService, CollaborationService, RightsService, ExportService, AIProvider,
VideoBackend, PluginBackend.

PRACTICE
small commits, tests, migrations, no god components, dependency injection,
UUID/ULID durable IDs rather than Date.now+Math.random, structured errors,
capability checks, accessibility, profiling and documentation.

FOR EACH FEATURE RETURN
current state, files changed, architecture, code, tests, migration, capability
limits and remaining gaps.

DEFINITION OF DONE
Real behavior, persisted, undoable where appropriate, sync-safe when
collaborative, documented, tested, accessible, and handles offline/error states.

START
Audit Phase 0/1 and implement one vertical slice:
Create Project -> import audio -> persist locally -> reopen -> play on real
timeline -> export a test/master render.
Do not start social/blockchain/marketplace/advanced AI until this is reliable.
