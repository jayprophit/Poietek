WEB V1
WebAudio AudioContext.
AudioWorklet for custom scheduler/DSP when required.
Decoded AudioBuffer exists only in runtime cache.

NATIVE LATER
Rust/C++/platform backend behind same contract.

CLOCK
Canonical sample clock.
Project musical position derived from:
sample position -> seconds -> tempo map -> ticks/bars.

PPQ default: 960.

SCHEDULING
Use lookahead scheduling from audio clock.
Never setInterval as timing authority.

For Web V1:
- UI/control timer may wake scheduler.
- events scheduled against AudioContext.currentTime sufficiently ahead.
- scheduler window dynamically sized.
- underrun telemetry.

CLIP PLAYBACK
Clip defines:
assetId
timeline start/duration
source offset/duration
gain
fades

At playback:
resolve assetId -> decoded runtime buffer
calculate overlap with transport
create/schedule source
apply gain/fade
connect graph.

SEEK
Stop scheduled sources.
Increment transport generation.
Rebuild schedule from new position.
Old generation callbacks ignored.

LOOP
Transport loop is authoritative.
Scheduler splits events crossing boundary.

MUTE/SOLO
Calculate audible set before scheduling/mixing.
Do not merely hide UI.

GAIN
Store dB canonical.
Convert:
linear = 10^(dB/20)

PAN
V1 equal-power stereo pan where backend supports.

FADES
Sample/time-based gain ramps.
Prevent clicks.
Fade handles persist in project.

IMPORT
File picker
-> stream/read
-> SHA-256
-> copy/reference into local AssetStore
-> metadata decode
-> waveform worker
-> project Asset
-> AudioClip.

ASSET STORE WEB
IndexedDB for metadata.
OPFS preferred for large local media when available.
Fallback Blob/IndexedDB with capability warning.

RUNTIME AUDIO CACHE
LRU decoded buffers.
Key: contentHash + decode settings.
Never serialized.

WAVEFORM
Generate multi-resolution peak pyramids:
min/max per block.
Store derived cache keyed by source hash/version.

RECORDING V2 OF ENGINE
Input backend
-> ring buffer / MediaStream strategy on web
-> local staging
-> finalize asset
-> hash
-> clip.
Recording must not depend on remote upload.

OFFLINE RENDER
V1 can use OfflineAudioContext for supported native WebAudio graph.
Render same canonical graph.
Third-party/native plugin host later gets its own render adapter.

METERS
Realtime thread writes compact peak/RMS telemetry.

PERFORMANCE BUDGET INITIAL PLACEHOLDERS
These are engineering targets to benchmark, not public promises:
- no avoidable audio underruns in 30-minute V1 fixture.
- UI actions must not block callback.
- waveform generation off main thread.
- project with 16 stereo clips opens from local store without decoding all clips at once.
