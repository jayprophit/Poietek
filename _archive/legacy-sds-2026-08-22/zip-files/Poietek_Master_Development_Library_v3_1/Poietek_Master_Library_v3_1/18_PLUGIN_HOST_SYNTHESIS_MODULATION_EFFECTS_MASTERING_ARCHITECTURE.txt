POIETEK / STUDIO DAW STATION (SDS)
MASTER DEVELOPMENT LIBRARY — VERSION 1.3 ADDENDUM

18 — PLUGIN HOST, SYNTHESIS, MODULATION, EFFECTS & MASTERING ARCHITECTURE
=======================================================================

PURPOSE

This document converts the creator-supplied research on virtual instruments,
modulators and effects into an original Poietek/SDS architecture.

The supplied material grouped virtual studio tools into three useful creative
families:
1. Synthesizers / sound generators.
2. Modulators / movement creators.
3. Effects / sound processors.

That framing is retained because it is useful for users, but one architectural
correction is required:

PLUGIN ROLE and PLUGIN FORMAT are separate dimensions.

Examples:
- "Instrument" is a role.
- "Effect" is a role.
- "Modulator" is a role.
- VST3, AU, CLAP, LV2 and AAX are formats/APIs/ecosystems.

A third-party wavetable instrument may be VST3, CLAP or AU.
A native Poietek instrument may use no external plug-in format at all.
A Poietek modulator may drive both native and hosted parameters.

The goal is therefore TWO connected systems:

A. POIETEK NATIVE SOUND PLATFORM
Built-in synths, samplers, modulators, processors, analyzers and mastering tools.

B. THIRD-PARTY PLUGIN HOST
Loads external plug-ins where the operating system, licence, security model and
plug-in format permit.

Do not clone proprietary DSP or interfaces. Study published capabilities,
workflow principles and open standards, then implement original designs.

1. RESEARCH UPDATE — CURRENT VERSIONS / VERIFIED DIRECTIONS
------------------------------------------------------------------------------

The creator-supplied comparison referenced several older product generations.
As of August 2026, first-party sources show important evolution:

Xfer Serum:
The current product is Serum 2. It now combines wavetable, multisample, ordinary
sample, granular and spectral oscillator types. Its current page also describes
sample slicing, real-time score extraction, spectral resynthesis and multiple
warp/modulation options.

Vital:
Current first-party material still emphasizes spectral-warping wavetable
synthesis, highly visual feedback, drag-and-drop modulation, editable LFOs,
audio-rate modulation, MPE and microtonal support. Vital's current Basic tier
states that the complete synthesizer feature set is available, with paid tiers
adding content/services.

Spectrasonics Omnisphere:
Current first-party pages emphasize a broad hybrid architecture: sample +
real-time synthesis, wavetable/granular/FM/ring modulation, deep modulation,
layering, user-audio import, effects and extensive physical-hardware integration.
Current product pages also emphasize a much broader hardware-profile system than
the older comparison material.

Arturia V Collection:
The current V Collection 11 Pro page describes a large instrument family
spanning modeled analog/digital instruments, sampled/acoustic hybrids, unified
preset browsing, hardware mapping and tutorials. The clean-room lesson is not
"copy classic synth panels"; it is "many different engines can share one
consistent browser, macro and controller layer."

Cableguys ShaperBox:
Current first-party material describes a multi-effect modulation environment
containing Reverb, Time, Drive, Noise, Liquid, Filter, Crush, Volume, Pan and
Width shaping, with waveform editing and multiband/rhythmic processing.

Xfer LFOTool:
Current first-party page describes customizable point/tension LFO curves,
multiple simultaneous graphs, BPM/Hz operation, sample-accurate sync and MIDI CC
output. The key transferable principle is that a modulation source can be a
first-class reusable control signal rather than a feature hidden inside a synth.

Soundtoys Tremolator:
Current first-party material describes tempo-synchronized tremolo/auto-gating,
programmable rhythmic patterns and dynamic response. The transferable principle
is musically synchronized modulation with custom curves and envelope-following.

FabFilter Pro-Q:
The creator supplied Pro-Q 3; the current official product is Pro-Q 4. Current
documentation includes static EQ, dynamic EQ, spectral dynamics, linear phase,
mid/side-related workflows and highly contextual controls. The clean-room lesson
is progressive disclosure: advanced controls appear when the user needs them.

Soundtoys 5:
Current first-party material describes a unified effects collection and Effect
Rack combining saturation, delay, pitch, modulation, filter and spatial effects.
The transferable principle is an effects-container workflow where creative chains
can be saved as a single reusable unit.

Valhalla VintageVerb:
Current first-party material describes a collection of distinct algorithmic
"modes" with different sonic characters. The clean-room lesson is to expose
meaningful high-level algorithm choices while keeping a compact control surface.

iZotope Ozone:
The creator supplied Ozone 11; current first-party material is Ozone 12.
Current Ozone 12 materials describe a modular mastering hub, editable individual
modules, track/reference workflows, AI-assisted mastering, dynamic EQ, limiting,
imaging, excitation, stabilizing, stem-aware tools and explicit user control.
The transferable lesson is "assistant proposes a chain, engineer remains in
control."

3. PLUGIN FORMAT POLICY
------------------------------------------------------------------------------

3.1 VST3

Priority: HIGH for desktop.

Current Steinberg first-party developer material states that VST technology /
the current VST3 SDK is open source under the MIT licence, while the VST name and
logo remain Steinberg trademarks with separate usage rules.

Poietek implications:
- Implement VST3 hosting on Windows/macOS/Linux desktop where technically stable.
- Preserve Steinberg copyright/licence notices as required.
- Follow trademark/logo usage rules if displaying official branding.
- Create automated compatibility tests.
- Do not support abandoned VST2 by default.

3.2 CLAP

Priority: HIGH for desktop.

The current CLAP reference repository describes:
- stable ABI;
- plug-in/host objects;
- state;
- parameters;
- audio/note ports;
- real-time/offline rendering;
- latency/tail reporting;
- GUI;
- voice information;
- threading support;
- preset discovery/load;
- host-provided track context;
- remote controls;
- modulation/note-expression-oriented extensions.

The reference implementation is MIT licensed.

Poietek implications:
CLAP should be a first-class host target alongside VST3 because its architecture
fits Poietek's modulation-heavy, MPE and future-extension goals.

3.3 AUDIO UNIT

Priority:
HIGH on macOS.
HIGH for AUv3 interoperability on Apple mobile where practical.

Apple currently documents AUv3 hosting for macOS and iOS and recommends AUv3 for
new development, while AUv2 is in maintenance mode.

Poietek implications:
- macOS: host appropriate AU/AUv3 plug-ins.
- iOS/iPadOS: support AUv3 extensions where platform rules permit.
- isolate platform-specific state from canonical Project state.
- store component identity + version + serialized state + freeze fallback.

3.4 LV2

Priority:
MEDIUM, especially Linux/open-source ecosystem.

Retain as a planned format from the broader Poietek specification.
Before implementation, verify current LV2 SDK/API/licensing and create a dedicated
format adapter and validation suite.

3.5 AAX

Priority as HOST: LOW / NOT INITIAL TARGET.

Avid's current developer site describes the AAX SDK as a development kit for
creating AAX plug-ins for Pro Tools, VENUE S6L and Media Composer, with separate
commercialization/signing requirements.

Poietek should NOT casually promise to "host AAX plug-ins."
Treat AAX as:
- a possible future export/build target if Poietek later ships its own plug-ins;
- subject to Avid licensing, signing and developer-program rules.

Do not display AAX in Poietek's "supported host formats" until an actual legal
and technical host path exists.

3.6 INTERNAL POIETEK PLUGIN API

Required for:
Web/PWA
portable native modules
community extensions
safe built-in modules
future cloud render workers

This API should be capability-based and may have:
- native Rust/C++ backend implementation;
- WASM implementation for portable processing;
- JavaScript/TypeScript only for non-realtime UI/control extensions.

Do not run arbitrary JavaScript on the audio thread.

5. PLUGIN SCANNING / FAILURE CONTAINMENT
------------------------------------------------------------------------------

Never scan third-party plug-ins inside the main DAW process if avoidable.

Scanner process:
1. discover candidate binaries/bundles;
2. launch isolated scanner;
3. load one plug-in;
4. inspect metadata/I/O;
5. open/close editor where safe;
6. serialize test state;
7. perform short render;
8. record crash/hang;
9. save compatibility result;
10. unload.

States:
UNSCANNED
SCANNING
VALID
WARNING
QUARANTINED
BLOCKED
MISSING
VERSION_CHANGED

A plug-in crash during scanning must not crash the studio.

A plug-in that crashes three times in the same project can automatically reopen
disabled while preserving its state.

------------------------------------------------------------------------------
6. PLUGIN SANDBOX
------------------------------------------------------------------------------

Desktop:
Prefer a separate process or process pool for untrusted third-party plug-ins.

Tradeoffs:
- stronger crash isolation;
- IPC overhead;
- GUI embedding complexity;
- real-time scheduling design;
- shared-memory audio buffers required.

Modes:
SAFE
NORMAL
LOW-LATENCY TRUSTED

User can override with warnings.

Never silently give plug-ins unrestricted:
filesystem
network
microphone
camera
project database
user credentials.

Legacy plug-in APIs may not support capability sandboxing perfectly, so Poietek
must distinguish "OS-process isolated" from "fully permission sandboxed."

10. AUTOMATION AND MODULATION ARE DIFFERENT
------------------------------------------------------------------------------

AUTOMATION
Timeline-owned deterministic parameter values.

MODULATION
Continuous relationship between a source and destination.

Example:
Filter cutoff automation = producer drew a curve over bars.
Filter cutoff modulation = LFO moves cutoff around that automation baseline.

EffectiveValue =
Base
+ Automation
+ ModulationSum
then clamped/transformed according to parameter semantics.

Plug-in formats differ in how deeply they support modulation. The host adapter
must translate gracefully.

25. ROUTING / FEEDBACK SAFETY
------------------------------------------------------------------------------

Modular routing is powerful but can explode numerically or sonically.

Rules:
detect direct zero-delay feedback loops.
Require explicit feedback node.
Clamp/soft-limit safety path optionally.
Display feedback warning.
Mute on NaN/Inf.
Protect user speakers.

Provide a global Panic command:
stop transport
all notes off
reset feedback
mute plugin processes if necessary.

  noticeRequirements

  approvedBy

Do not confuse:
"product can host VST3"
with
"we can copy code from a commercial VST3 plugin."

Hosting a format and reproducing a product's DSP are entirely different legal
questions.

34. AI SOUND DESIGN
------------------------------------------------------------------------------

AI assistant can:
describe a synth patch
create editable oscillator/filter/modulation commands
suggest modulation
search presets
match a reference characteristic at a high level
create an effect chain
explain why chain is proposed
suggest mastering chain

Example:
"Make this bass wider above 180 Hz but keep sub mono."

AI proposes:
- mid/side split;

For third-party plugins:
AI may use exposed parameters but must not assume semantic meaning when parameter
metadata is insufficient.

49. CLEAN-ROOM RULES
------------------------------------------------------------------------------

Allowed inspiration:
- published workflow concepts;
- public manuals;
- public specifications;
- open-source standards under their licences;
- independent DSP theory;
- measurements/research conducted lawfully;
- user feedback.

Do not copy:
- proprietary code;
- factory presets;
- wavetables;
- impulse responses;
- protected samples;
- interface artwork;
- product-specific text;
- proprietary hardware model names for Poietek native products;
- undocumented protocols;
- patented algorithm implementations without review/licensing.

"Analog-inspired" is different from claiming an exact model of a named device.
